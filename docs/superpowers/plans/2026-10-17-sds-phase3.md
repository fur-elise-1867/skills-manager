# SDS Phase 3 — Multi-agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cài và quản lý bốn agent theo global/project, nhiều target và preset một lần, giữ kết quả từng cặp skill/target.

**Architecture:** Mở rộng SDS coordinator và journal hiện có; một batch chứa các operation đơn target, không transaction toàn batch. Target resolution thuộc backend; UI gửi lựa chọn có định danh, không tự cung cấp destination đáng tin cậy. Tái sử dụng lifecycle Phase 2 sau khi G2 được nghiệm thu.

**Tech Stack:** React 19/TypeScript, Tauri 2/Rust, SQLite, Vitest/Testing Library, Rust tests trên temp roots.

**Spec:** [Delivery design §4–8,10–11](../specs/2026-10-16-sds-app-delivery-design.md), [SRS INS/PRE/MCP](../../sds-phase1/SRS.md), [review và gate G2](2026-10-17-sds-phase3-5-review.md).

Trạng thái: draft develop & test, chưa thực thi. Paths tương đối root app tại baseline `be1cd17` rồi tích hợp Phase 2; không code trên checkout tài liệu `161f6d4`. Trước execution tạo/reuse worktree bằng workflow using-git-worktrees và mang theo docs mới. `R` = `src-tauri/src/sds`; `F` = `src/features/sds`.

**Dependency update 2026-10-17:** [plan Phase 2](2026-10-17-sds-phase2.md) đã định nghĩa WorkspaceRef/TargetSelection, versioned operation contexts, migration dispatcher, snapshots/replacement và selected-update grouping. P3.1 đối chiếu handoff P2.9; mở rộng các interface đó, không tạo implementation song song. General batch P3.3 tái sử dụng grouping/locking của P2.5.

## Global Constraints

- Windows; English mặc định; copy deployment độc lập mỗi target. Một lượt chọn global hoặc một project, không trộn nhiều project trong cùng review.
- Store: chỉ thêm file/folder/package mới; không sửa, di chuyển hoặc xóa file hiện có, kể cả cấu hình, dependency manifest, security hoặc migration cũ.
- Database Store: chỉ thêm bảng/job/đối tượng mới khi cần. Không sửa hoặc xóa bảng, cột, index hay đối tượng hiện hữu. Không chạy script reset/recreate DB dùng chung.
- HTTP chỉ cho loopback trong cấu hình development. Môi trường nội bộ dùng HTTPS có xác minh chứng chỉ; không cho tắt TLS verification.
- Không chạy script package; không ghi vào rules/agents/config/mcp.json; không auto-install agent hoặc auto-update skill.
- Token chỉ backend/keyring; không public updater/Git/CLI; fixture không fallback tự động.
- UI baseline 1440×860, minimum 1100×640; dùng token đã chốt trong amendments Phase 0–1, không reopen branding/theme từ variant Stitch.
- Không tự ghi đè unmanaged content/local edits. Các giới hạn package hiện có được giữ; không nới chúng để làm test xanh.

## Review Focus

1. Hai lựa chọn/case/override trỏ cùng đích: một operation, không ghi đè do trùng key (P3.2–3).
2. Target/project bị thay hoặc junction sau review: REVIEW_REQUIRED trước write (P3.2–3).
3. Crash sau target A commit trước target B: A không cài lại khi retry/restart (P3.3).
4. Mixed AIPro/non-AIPro và null MCP: acknowledgement đúng operation, agent khác không có dấu passed giả (P3.2–3).
5. Preset chứa release unavailable/account cũ/local cache mất: không silently thay release hoặc dùng quyền cũ (P3.4).

## P3.3 — Batch coordinator và kết quả/retry/cancel từng cặp

**Depends:** P3.2. **SRS:** INS-07, MCP-04/05. **Screens:** W04,W06.

**Interfaces:** `BatchInstallRequest { items: Vec<InstallRequest> }`; `BatchItem { itemId, operationId, skillId, releaseId, target, preflightError? }`; `PreparedBatch { batchId, items }`; `BatchResult { batchId, items: [{ itemId, operationId, result: OperationResult }] }`. `BatchService::prepare(request) -> PreparedBatch`, `execute(batch_id, acknowledged_operation_ids: Vec<String>) -> BatchResult`, `cancel(batch_id) -> BatchResult`, `retry_failed(batch_id) -> PreparedBatch` (async Result<…, SdsError>). IPC `sds_prepare_batch`, `sds_execute_batch`, `sds_batch_status`, `sds_cancel_batch`, `sds_retry_failed_batch`; execute returns batchId promptly and workers publish progress; status remains authoritative.

Proposal: execute serially initially; no need parallel filesystem writes. Deduplicate exact skill/release/canonical target; same destination with different skill/release is conflict before any write. Failed preflight items stay visible; valid items execute only after review. Retry creates new plans/IDs only for failed items, rechecks ACL/MCP/target; cancelled items require explicit new selection. RecoveryRequired must recover before retry. Completed items are never replayed.
