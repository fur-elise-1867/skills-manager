# Phase 2 native acceptance checklist

Use fixture-free development installer against the identity-verified dedicated Store; use only task-owned global/project test directories. Internal artifact must use HTTPS-only configuration. Do not infer company AIPro runtime recognition from synthetic skill files.

- [ ] Upgrade pilot application with prior cache/deployments and inspect migrated data/session; retain a backup before first new-runtime launch.
- [ ] Install a real Store release in global and two registered project roots; compare independent target files and global MCP location.
- [ ] Check metadata without package download, select one target and verify other release IDs/baselines/files remain unchanged.
- [ ] Edit selected target, choose Keep current and verify bytes; then choose Back up and update and verify snapshot and new release/MCP review.
- [ ] Inject a snapshot destination failure; verify no target replacement and a clear retryable workflow after correcting the owned failure.
- [ ] Capture a manual snapshot, edit again and restore with current-content protection; verify original baseline still reports saved edits as Modified.
- [ ] Remove a modified target with selected backup; verify other targets and Library cache; delete only an unreferenced cache and restore its independent snapshot.
- [ ] Verify Store outage offers explicit Use cached copy for the prior authorized account; expired/sign-out/403 cannot use that path; reconnect triggers a real request.
- [ ] Restart after an interrupted owned operation and verify authoritative status and retained evidence; do not clear foreign files to force success.
- [ ] Inspect1440×860 and minimum1100×640, light/dark, keyboard focus, long paths, loading/empty/error/recovery messages, W09/W10/W11/W13 mapped layouts.
- [ ] Record actual installer hashes, operation IDs, paths, observed state and any unmet case in acceptance evidence. Checkbox completion requires an actual native observation; automated tests are recorded separately.
